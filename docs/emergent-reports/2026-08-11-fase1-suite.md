## Fallos y causa raíz

### 1. [ENTORNO] 28 errores de setup + 2 fallos de login al invocar pytest manualmente
- **Síntoma:** `Login failed for manager@nexus.com: 404 404 page not found`.
- **Causa raíz:** `tests/conftest.py` usa `BASE_URL = os.environ.get("REACT_APP_BACKEND_URL", "<dominio preview viejo de un fork anterior>")`. Al correr pytest manualmente en este pod, esa variable no estaba exportada al shell (solo vive en `frontend/.env`), así que caía al dominio por defecto obsoleto → 404.
- **Intento con `REACT_APP_BACKEND_URL=http://localhost:8001`:** resolvió el 404, pero expuso un segundo síntoma (ver #2).
- **Clasificación:** entorno/invocación, no bug de producto. El pipeline de GitHub Actions (`.github/workflows/ci.yml`) ya exporta esta variable correctamente; en este pod hay que exportarla a mano apuntando al dominio preview real.
- **Corrección aplicada:** ninguna en código (no hay forma estable de "arreglar" un dominio de preview que cambia en cada fork). Se documenta la invocación correcta:
  ```
  REACT_APP_BACKEND_URL=https://clipper-manage-1.preview.emergentagent.com python -m pytest tests/ -q
  ```

### 2. [ENTORNO] `assert 401 == 200` tras login exitoso, usando `http://localhost:8001`
- **Causa raíz:** `COOKIE_SECURE` (backend/server.py) es `true` por defecto; la cookie `session_token` se emite con `Secure`. Sobre `http://` plano esa cookie nunca se reenvía, así que toda llamada autenticada posterior da 401. CI evita esto fijando `COOKIE_SECURE=false` y `CORS_ORIGINS=http://localhost:3000` solo en su propio entorno aislado de un solo uso.
- **Decisión:** NO se tocó `COOKIE_SECURE` ni `CORS_ORIGINS` del `.env` compartido (cambiarlos afectaría la sesión real de Preview y exigiría reiniciar el backend — prohibido por las reglas). En su lugar se corrió la suite contra el dominio `https` real de Preview, donde las cookies `Secure` funcionan sin tocar nada.
- **Clasificación:** entorno/invocación, no bug de producto.

### 3. [DATO SEMILLA] `test_status_returns_contracted_enabled` y `test_create_and_list_conversation` (Nexus AI)
- **Síntoma:** `assert d["contracted"] is True` → `False`; creación de conversación → 403.
- **Causa raíz:** la organización demo (`org_demo001`) en la base `test_database` no tenía `nexus_ai_contracted`/`nexus_ai_enabled` seteados.
- **Corrección:** se ejecutó `seed_data.py` contra `test_database` (autorizado explícitamente en Preview por el punto 1 de la tarea). El script es idempotente (`$set` solo si falta el flag) — no tocó clientes/usuarios reales, solo backfill de la org demo.
- **Resultado:** ambas pruebas pasan.

### 4. [BUG REAL, corregido] `seed_data.py` caía en una base de datos distinta cuando falta `DB_NAME`
- **Evidencia:** al correr `python seed_data.py` sin `DB_NAME` exportado, el script conectó e imprimió `Connecting to: barbershop` — una base **distinta** de la real (`test_database`), dejando datos duplicados huérfanos en una base que ninguna otra parte del sistema usa. Todos los demás scripts del backend (`server.py`, los 9 demonios, `fix_total_visits.py`, etc.) usan `os.environ["DB_NAME"]` (sin default) y fallan rápido si falta — `seed_data.py` era el único con un default silencioso y obsoleto (`'barbershop'`, nombre de una versión anterior de la app).
- **Riesgo:** cualquiera que corra el script de seed sin exportar `DB_NAME` puebla silenciosamente una base que nadie lee, sin ningún error visible.
- **Corrección (mínima, en `backend/seed_data.py`):**
  ```diff
  - mongo_url = os.getenv('MONGO_URL', 'mongodb://localhost:27017')
  - db_name = os.getenv('DB_NAME', 'barbershop')
  + mongo_url = os.environ['MONGO_URL']
  + db_name = os.environ['DB_NAME']
  ```
- **Prueba agregada:** `backend/tests/test_seed_data_env.py` — verifica que `seed_database()` lanza `KeyError` si `DB_NAME` no está en el entorno (ya no hay fallback silencioso).
- **Limpieza:** se detectó y se **borró** la base `barbershop` huérfana creada por mi primera ejecución accidental del script (no tenía ningún consumidor en el código; no era un dato real de cliente).
- **Commit:** `20dec72` en `emergent/fase1-suite`.

### 5. [PRUEBA OBSOLETA, no modificada] `test_mirror_rejects_unsafe_keys_and_oversize_payload`
- **Síntoma (intermitente, depende del orden de ejecución dentro del mismo worker de `pytest-xdist`):** `DID NOT RAISE ValueError` al subir un payload de 15 MB+1 con namespace válido.
- **Causa raíz:** `media_mirror.py` está diseñado para que, cuando Cloudflare R2 está configurado (`object_storage.enabled()`), el límite dured de 15 MB de la copia en MongoDB **ya no aplique** (R2 permite hasta 50 MB) — así lo documenta el propio docstring del archivo: *"Cloudflare R2 (...; no size problem)"*. Como `backend/.env` ya tiene credenciales reales de R2 (agregadas en una tarea anterior), ese comportamiento es el correcto y esperado. La prueba data de antes de que R2 estuviera configurado y asume que el límite de 15 MB siempre aplica.
- **Por qué es intermitente:** dentro de un mismo proceso worker de pytest, en cuanto *cualquier otro* módulo de test importa `server.py` (que carga `.env` vía `load_dotenv()`), `os.environ` queda poblado con las credenciales de R2 para el resto de esa sesión — por eso falla solo cuando corre junto a la suite completa y no en aislamiento.
- **Efecto secundario detectado y limpiado:** al correr la suite completa, esa prueba sí llegó a escribir un objeto real de 15 MB de basura (`nexus/platform/x.webp`) en el bucket R2 `nexus-media` de producción. **Se verificó y se borró** ese objeto (`object_storage.delete_object('platform', 'x.webp')`); el bucket queda limpio.
- **Decisión:** no se modificó el test ni el código — es un cambio de comportamiento intencional (R2 ya activo), no un bug. Se deja documentado para que Felipe/Claude decidan si actualizar la aserción del test para reflejar el nuevo límite (50 MB vía R2) cuando se revise la rama.
- **Riesgo operativo a vigilar:** cualquier prueba futura que suba payloads grandes "de prueba" ahora puede terminar escribiendo de verdad en el bucket R2 real, porque las credenciales ya son reales. Vale la pena que el equipo decida si quiere un bucket/`R2_BUCKET` separado para CI/tests.
